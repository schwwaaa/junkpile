Layer 0 · Read this first

What Junkpile is #

Junkpile is a developer library of small Tauri applications for live visual work. Each project isolates one rendering or input architecture so you can verify a known baseline, understand its data flow, and then build a specific idea without inheriting an undocumented prototype.

A

Baseline

The smallest useful example of one architecture, kept readable and application-neutral.

B

Paired comparison

Where possible, the same graphics concept exists in v1/v2 and single/two-window forms.

C

Unique example

An artistic or product-specific branch created only after the baseline is accepted and preserved.

Important scope boundaryEvery current renderer runs inside the Tauri WebView. The repository does not yet contain a native Rust wgpu, Metal, Vulkan, or DirectX surface family.

Layer 1 · Fast path

Run an example #

  1. Install the platform prerequisites. You need Rust through rustup, Node.js/npm, and the operating-system packages required by Tauri.
  2. Choose one independent project. There is no root workspace command. Start with v1/p5-tauri-single-template for the shortest learning path.
  3. Use the local npm scripts. This selects the correct Tauri CLI major declared by that project instead of an unrelated global CLI.
  4. Confirm the baseline before editing. Verify the app launches and the main control/render path behaves as described.
terminal · first recommended example
cd v1/p5-tauri-single-template
npm install
npm run dev

Build an installable application from the same project directory:

terminal
npm run build
Why not cargo tauri dev from anywhere?The examples deliberately pin v1 or v2 of @tauri-apps/cli in each local package.json. npm run dev is the most reliable way to keep the CLI, Cargo dependencies, and config schema aligned.
Layer 1 · Decision guide

Choose the smallest matching baseline #

Do not begin with the most advanced example merely because it contains more features. Start with the fewest layers that prove your idea.

Start with p5 single-window. It has the shortest path from a parameter to a shader uniform and visual result. Move to the WS variant only when separate controls/output matter.
MIDI for hardware, OSC for network software, WebSocket for a second app window. MIDI and OSC currently exist only in the v1 set.
Webcam first, feedback second. Confirm camera permission, video readiness, and texture upload in the webcam baseline before adding persistent framebuffer state.
Raw WebGL or external GLSL. Raw WebGL exposes the complete browser GPU setup. External GLSL adds runtime file loading and a cleaner shader-authoring boundary.
GoalFirst choiceMove deeper when…
Prototype a shaderp5 singleYou need explicit graphics plumbing or shader file loading.
Understand browser GPU setupraw WebGL singleYou need runtime-editable external shaders.
Edit a separate shader fileGLSL singleYou need controls on another display.
Process live camera frameswebcam singleYou need persistent trails or simulation state.
Create recursive trailsfeedback singleYou need controls separated from output.
Use a physical controllerMIDI v1You need custom mappings, multiple devices, or a v2 port.
Control from creative softwareOSC v1You need discovery, feedback messages, or multi-node networking.
Layer 2 · Mental model

Six concepts explain most of the repository #

WebView

The embedded browser surface where HTML, JavaScript, p5.js, camera APIs, and WebGL run.

Rust host

The native Tauri process. It creates the application and owns MIDI, OSC, or the local WebSocket relay when needed.

State

The current parameter values. Single-window state is direct; two-window state is serialized and transported.

Render loop

A repeated function that reads state, uploads uniforms or textures, and draws the next frame.

Shader

GPU code that determines how vertices or pixels are produced. Current examples use WebGL-era GLSL.

Baseline evidence

A source review, successful build, runtime test, or cross-platform test are different levels of confidence.

Layer 3 · Graphics

Rendering families #

Each family teaches a different amount of graphics plumbing. The final pixels may look related, but the code boundaries are intentionally different.

p5.js baseline

The quickest path from a creative sketch to a desktop app.

p5.js creates the WEBGL canvas, manages the animation loop, compiles embedded shader strings, and uploads uniforms through a compact creative-coding API.

What you learnCanvas creation, shader uniforms, p5's draw loop, and lightweight UI binding.
When to choose itStart here when speed of iteration matters more than seeing every WebGL primitive.
Raw WebGL baseline

The browser graphics pipeline with every important step visible.

These examples request a WebGL context, compile and link shaders, create a full-screen quad, locate uniforms, resize the viewport, and issue draw calls without a graphics framework.

What you learnShader compilation, program linking, buffers, uniforms, viewport management, and draw calls.
When to choose itUse this family when you want the clearest low-level browser GPU baseline.
External GLSL baseline

Raw WebGL with shader source kept in a separate file.

The fragment shader lives in shader.frag and is loaded at runtime. This isolates shader authoring from host JavaScript and introduces explicit loading and compile-error handling.

What you learnRuntime asset loading, shader iteration, compiler errors, and code separation.
When to choose itChoose this when the shader itself is the primary artifact or future editor target.

Webcam baseline

Live camera capture uploaded into a WebGL texture every frame.

JavaScript requests camera access with getUserMedia, routes the stream through a hidden video element, and uploads each ready frame into a GPU texture for real-time processing.

What you learnPermissions, MediaDevices, video readiness, texture upload, camera selection, and live effects.
When to choose itUse this baseline for camera-reactive tools, installations, and visual instruments.

Feedback baseline

Stateful image processing with alternating framebuffer textures.

Two framebuffer textures alternate roles. Each frame samples the previous state and webcam texture, writes the next state, displays it, then swaps references.

What you learnPing-pong framebuffers, persistent GPU state, simulation/display separation, and state reset on resize.
When to choose itThis is the advanced baseline for trails, datamosh, reaction systems, and recursive image processes.

Layer 3 · Hardware and network inputs

Native input bridges #

MIDI: hardware bytes become structured frontend events

Rust uses midir because Web MIDI support inside desktop WebViews is inconsistent. Rust owns port enumeration, connection state, and message callbacks. JavaScript maps the resulting events to visual parameters.

MIDI path

ControllerCC · note · pitch bend
→
midir in Rustnative port + callback
→
Tauri eventstructured message
→
p5 uniformsnext frame

Current gap: there is no Tauri v2 MIDI baseline yet. A trustworthy port should document v2 commands/events, capabilities, permissions, and platform testing.

OSC: UDP packets become creative parameter messages

Rust binds UDP port 9000 through Tokio, decodes packets with rosc, and emits messages into JavaScript. Creative address mapping remains in the frontend so it can change without rebuilding Rust.

→

→

Migration checklist for a new pair
  • Pin the correct local @tauri-apps/cli major.
  • Pin matching tauri and tauri-build majors.
  • Convert tauri.conf.json to the target schema.
  • Verify product name, identifier, windows, CSP, and icons.
  • Verify every configured window URL exists.
  • Verify commands/events against the target generation.
  • Run both development and release builds.
  • Test permissions and lifecycle behavior on each target OS.
  • Document only differences that are actually present.

Layer 4 · Environment and platforms

Development setup #

Core prerequisites

  • Rust installed through rustup.
  • Node.js and npm.
  • macOS: Xcode command-line tools.
  • Windows: Microsoft C++ build tools and WebView2.
  • Linux: WebKitGTK and distribution-specific Tauri development packages.

Camera validation

A camera example crosses six layers: device availability, WebView permission request, user permission, getUserMedia(), video readiness, and WebGL texture upload. Test them separately; a black image is not automatically a shader failure.

MIDI and OSC notes

MIDI

Verify hardware in the OS MIDI utility. On macOS, the IAC Driver provides virtual routing. Linux builds may require ALSA development packages and device permissions.

OSC

Point the sender at the computer running Junkpile and UDP port 9000. Firewalls, address spelling, and argument types are common failure points.

Offline p5.js

Several p5-family examples currently load p5.js from cdnjs. To make one self-contained, vendor a known p5.js file into src/vendor, update the script path, tighten the CSP, and record the vendored version/license.

Layer 4 · Failure diagnosis

Troubleshooting by layer #

Start with the earliest layer that could fail. Do not rewrite shaders before confirming that the app, window, external script, media permission, or network listener actually started.

Wrong Tauri CLI generation — Configuration schema errors or unknown fields

Run npm install and npm run dev inside the example. The project-local CLI major must match its Rust dependencies and config schema.

WebSocket port already in use — Two-window controls and canvas remain disconnected

Only one current WS template can bind loopback port 2727. Stop the other template or change the Rust PORT constant and both frontend WS_URL values together.

Shader compilation failure — Blank canvas with a compiler log

Read the exact GLSL log. Check WebGL 1 / GLSL ES 1.0 syntax, precision, matching varyings, uniform names, compile-time loop constraints, and unsupported WebGL 2 features.

Blank p5.js canvas — No visual output in a p5 example

Confirm the p5 CDN request succeeded, CSP permits cdnjs, createCanvas(..., WEBGL) ran, and there are no JavaScript or shader errors.

Blank raw WebGL canvas — Canvas exists but nothing draws

Confirm getContext('webgl'), shader compile/link status, nonzero dimensions, gl.viewport, the quad buffer, the attribute location, and the final draw call.

Camera permission or device failure — No devices, black frame, or rejected permission

Check OS permission, refresh device labels after permission, close apps that may hold the camera, verify the video ready state, then inspect texture upload errors.

Feedback clears after resize — Accumulated state disappears

This is expected because framebuffer textures are recreated at new dimensions. Preserving state requires explicit resampling.

MIDI device missing — Controller does not appear or connect

Use the debug action to print the exact port names Rust sees. Check OS MIDI tools, virtual ports, device permissions, and exclusive access.

OSC packets do not move controls — Sender appears configured but no parameters change

UDP has no connection handshake. Verify host, port 9000, OSC address, argument type, firewall, and the on-screen packet log.

Layer 5 · Create new work

Extend without destroying the baseline #

  1. Choose the nearest accepted baseline. Do not merge unrelated systems before each one works independently.
  2. Preserve it. Keep a clean commit, tag, or branch that remains a neutral reference.
  3. Change one architectural layer. Add a shader, input method, transport behavior, or native integration—not all four at once.
  4. Comment the reason. Explain boundaries, lifecycle constraints, platform behavior, and non-obvious tradeoffs rather than narrating syntax.
  5. Document the new behavior. Include purpose, prerequisites, architecture, file map, run/build steps, controls, extension points, troubleshooting, and validation evidence.

Glossary for new developers #

Baseline
A minimal, neutral example that proves one architecture before product-specific behavior is added.
Tauri
A Rust-based desktop application framework that hosts web frontend content inside an OS WebView.
WebView
The embedded browser engine used to render HTML/CSS/JavaScript in a desktop window.
WebGL
A browser API for GPU graphics. Current examples use a WebGL 1 style pipeline.
GLSL
The shader language used by the current WebGL examples.
Shader
A small GPU program. Fragment shaders determine pixel color; vertex shaders transform geometry.
Uniform
A value uploaded from JavaScript that remains constant during one draw call, such as time, hue, or intensity.
Texture
Image-like data stored on the GPU, including webcam frames and feedback state.
Framebuffer
An off-screen GPU render target. Ping-pong feedback alternates between two of them.
IPC / event bridge
Communication between frontend JavaScript and the Rust host process.
WebSocket
A persistent message transport. Junkpile uses a loopback relay for controls-to-canvas communication.
OSC
Open Sound Control, a network message format widely used by creative software.
MIDI
A hardware/software control protocol using notes, continuous controllers, pitch bend, and other messages.
CSP
Content Security Policy, which controls what scripts, assets, and network connections a WebView may use.

Build from a known baseline.

Junkpile keeps graphics, input, transport, and Tauri-generation decisions visible so developers can change one layer without guessing what the others are doing.
